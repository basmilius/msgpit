This covers the upstream user-facing feature set. It is a rewrite rather than a
byte-for-byte implementation. The tests establish parity for the listed cases,
not every possible malformed request or message.

## Deliberate differences

- The web interface uses Command Center's Messages layout and Desktop UI components.
- Sender DNS checks require an explicit button press. Opening a message or tab makes
  no outbound request. Link probes are also explicit.
- SpamAssassin is bundled and enabled in Docker. Its local rules run without network
  lookups or Bayesian learning. An external spamd remains configurable.
- HTTP and SMTP share one Rust process. Provider translations remain pure.
- Captures use a separate `msgpit-rust.sqlite` database. PHP captures are preserved
  but are not migrated. The original .eml download preserves the exact bytes.
- Captured HTML has a stricter sandbox. Scriptable MIME types download as binary;
  remote images are blocked. HTTP credentials are masked in stored request headers.
- Outbound probes, SMTP connections and message sizes have limits. Link checks
  stop after 50 URLs and refuse cloud metadata and link-local targets.
- A GitHub release publishes an image; pushing main does not automatically create
  a release. The container runs as uid 10001 and does not change ownership of an
  existing bind mount. Make the data directory writable for that uid.

Command Center project namespaces and assistant actions belong to that application,
not upstream Msgpit. Connecting Command Center to this standalone service remains a
separate task, as requested.
